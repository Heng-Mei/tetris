# 游戏模式、人机对战与攻击表 — 设计

日期：2026-10-17
状态：已确认，待实现计划

## 目标

在现有单机马拉松基础上，补齐现代俄罗斯方块常见的短局模式与人机对战，并让攻击规则可自定义，同时保持「无构建、无依赖、纯前端」的架构。

范围内：

- Marathon（现有）
- Sprint 40L（40 行竞速）
- Blitz（2 分钟限时冲分，等级提速）
- VS AI（人机对战，三档 AI）
- 自定义攻击表（图形编辑 + 文件导入导出）

范围外：联网对战、回放、排行榜、道具/技能、触屏操控、AI 的多步搜索与 T-Spin 做局。

## 架构

在现有模块上新增三个纯逻辑模块，DOM 相关改动集中在主循环与 UI：

```
js/modes.js         模式定义、模式时钟、结束判定、Blitz 重力曲线（纯逻辑）
js/attack.js        攻击计算、攻击表校验/预设、垃圾行插入与顶死判定（纯逻辑）
js/ai.js            候选落点枚举、棋盘评估、三档难度决策（纯逻辑）
js/attack-editor.js 攻击表图形编辑器（DOM）
```

修改：

- `engine.js`：新增 `insertGarbage`、`isToppedOut`；`lockPiece` 返回 `perfect`；不改现有手感/计分行为。
- `main.js`：模式选择、模式时钟、对手状态、AI 节拍、胜负结算、HUD 适配。
- `render.js`：抽出可复用的棋盘绘制函数，供对手小棋盘使用。
- `settings.js`：新增 `mode`、`aiDifficulty`、`attackTable` 默认值与校验，旧存档自动补默认。
- `ui.js`、`index.html`、`style.css`：模式选择、对手面板、攻击表入口与弹窗。

保持 `engine/handling/rotations/settings/attack/modes/ai` 无 DOM，Node 可直接测试。

## 模式规则

| 模式 | 时钟 | 结束条件 | 计分 |
|---|---|---|---|
| `marathon` | 从开局正计时 | 顶死 | 现有 Guideline 计分 |
| `sprint` | 从第一块出现起正计时 | 消满 40 行 → 完成；顶死 → 失败 | 不影响结果 |
| `blitz` | 2:00 倒计时 | 时间到 → 按分数结算；顶死 → 提前结束 | 现有计分 |
| `vs` | 正计时 | 任一方顶死；同帧双顶死判玩家负 | 现有计分，另计发送/接收攻击 |

- 模式时钟独立于 `game.time`：`start()` 后开始走，暂停、切后台、设置抽屉打开时停止；包含出生与消行延迟，Sprint 计时才公平。
- 切换模式立即重开当前局。
- Blitz 重力：`max(用户重力, 1 + (level - 1) * 0.6)` 行/秒，等级每 10 行 +1。等级仍只乘分数，不改变 Sprint/VS 的重力。
- Sprint 的 40 行指累计消行数；达到或超过 40 行立即完成，显示实际用时。
- Blitz 时间到与顶死同帧时，顶死优先，结果页显示「顶死」。

## 对战与垃圾行

- 双方各自持有独立 `game` 状态与 incoming 计数；共用同一旋转系统与攻击表。
- 锁定结算顺序（记锁定前的待接收为 `incomingBefore`）：
  1. 计算本次消行攻击（含 combo、B2B、Perfect Clear）；combo 用消行后的值，B2B 用消行前的状态。
  2. 先抵消自己的 incoming：`incomingAfter = max(0, incomingBefore - attack)`。
  3. 剩余攻击发给对方：`send = max(0, attack - incomingBefore)`，对方 `incoming += send`。
  4. 把自己的 `incomingAfter` 立即插入底部。
- 垃圾行：每行 1 个空洞、其余 9 格填灰；整行从底部插入并把现有内容上推。连续插入时避免与上一行同洞；随机源由调用方注入，测试可固定。
- 插入后若有任何方块进入顶部隐藏行（`y < HIDDEN`），该方顶死。
- 非 VS 模式不接收、不发送垃圾行。
- 面板展示：玩家与 AI 的「待接收 / 累计发送」数字；对手棋盘实时绘制。

## AI

- 每次落子枚举所有合法 `(rotation, x)`，模拟落地与消行，用一层启发式打分：
  `score = wClear*消行 - wHeight*总高度 - wHoles*空洞数 - wBump*崎岖度 - wMax*最大高度`。
- 选择最高分；难度通过落子间隔与失误率区分：
  - easy：900ms，35% 概率从前 3 名中随机选，评估权重加噪声
  - normal：450ms，12% 失误
  - hard：200ms，3% 失误
- AI 不做 Hold、不做 T-Spin 做局、不看下一块；不做多步搜索。
- AI 的消行同样走攻击表与 incoming 抵消；AI 顶死即玩家获胜。
- AI 只在 `running && !paused && mode === 'vs'` 时行动；暂停时不消耗节拍。

## 攻击表

数据结构：

```json
{
  "name": "Guideline",
  "base": {
    "single": 0,
    "double": 1,
    "triple": 2,
    "tetris": 4,
    "tspinMini": 1,
    "tspinSingle": 2,
    "tspinDouble": 4,
    "tspinTriple": 6,
    "perfectClear": 10
  },
  "b2b": 1,
  "combo": [0, 0, 1, 1, 2, 2, 3, 3, 4, 4, 4]
}
```

- `base` 按消行种类取值；T-Spin 优先于普通消行；0 行 T-Spin 不发攻击。
- `b2b` 只在「困难消行」（Tetris 或带消行的 T-Spin）且处于 B2B 时加一次。
- `combo[i]`：`i` 为本次消行后的连击数（首消为 0），超出数组长度时重复最后一项。
- `perfectClear` 在消行后棋盘全空时叠加。
- 最终攻击为非负整数；0 表示不发。
- 校验：所有数值取整并夹到 0–20；`combo` 长度 1–20，缺失字段用 Guideline 默认值；结构不合法则拒绝应用/导入。
- 预设：Guideline / 高攻击 / 低攻击。

图形编辑器（与旋转系统编辑器同风格）：

- 数值输入：9 个基础攻击值、B2B 加成。
- combo 表：逐项数字输入，可增删。
- 预设按钮、导入 JSON、导出 JSON、取消、应用。
- 界面不出现 JSON 文本框；JSON 只通过文件导入/导出。
- 应用后写入 `settings.attackTable` 并持久化；非法输入 toast 报错且保留原表。

## UI

- 顶栏新增模式下拉（Marathon / Sprint 40L / Blitz / VS AI）与 AI 难度下拉（仅 VS 显示）。
- 左栏 HUD：
  - Sprint：消行显示 `n / 40`，时间正计时。
  - Blitz：时间显示剩余 `m:ss`，等级正常显示。
  - VS：新增「攻击」行显示累计发送；对手面板显示其待接收。
- 右栏：VS 时用对手面板替换提示框，包含 AI 难度、对手小棋盘、待接收/发送数字；其他模式隐藏。
- 结算 overlay：
  - Sprint 完成：「40 行完成 · 用时 1:23」；失败：「顶死」。
  - Blitz：「时间到 · 分数 x」；顶死：「顶死 · 分数 x」。
  - VS：「胜利 / 失败」+ 双方消行与发送攻击。
- 设置面板新增「攻击表」区块，按钮打开编辑器。
- 小屏沿用现有收缩策略；对手棋盘固定小尺寸，不做分屏。

## 持久化与错误处理

- `localStorage['tetris.settings.v1']` 继续使用；新增字段通过合并默认值兼容旧存档。
- `attackTable` 损坏时回退 Guideline，不让页面启动失败。
- 导入设置（整包）时若含攻击表，同样校验；失败保留原设置。
- 对手状态不持久化，每局重建。
- 所有模式共用现有暂停逻辑；暂停时 AI 与模式时钟停止。

- 模式切换会重开；Sprint 完成与 Blitz 倒计时结算正确。
- VS 模式对手棋盘与攻击数字随消行变化，AI 会落子，任一方顶死结束。

- 刷新后模式、难度、攻击表保留；旧存档（无新字段）可正常启动。

## 已知取舍

- AI 只有一层评估，不会做 T-Spin 或留四消；hard 靠速度而非更强搜索。
- 垃圾行空洞随机，只避免相邻同洞，不做 per-column 计数与「messiness」规则。
- Blitz 重力曲线固定，不开放自定义；要改就改 `modes.js`。
- 对手棋盘放在右栏，尺寸明显小于主棋盘，不做等宽分屏。
- Sprint 不发送垃圾行，也不做「40 行后继续」的额外结算。
